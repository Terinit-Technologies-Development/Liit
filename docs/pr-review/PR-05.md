# PR-05 — Inbox, Direct Chat, Host Inquiries, and Social UI

## Objective

Rebuild the LIIT consumer messaging, host inquiries, and social coordination surfaces according to Instruction 5 product specifications and review feedback.

Key implementations:
1. **Host Booking Offer & Checkout Repair**:
   - Added canonical `tier-vip-tables` tier (`VIP Table Reservation (4 Guests)` at R1,500.00 / 150000 minor ZAR) to `midnightGroovesTiers` fixture.
   - Wired `beginCheckout(eventId, tierId)` in `InquiryThreadScreen` before navigating to Ticket Selection.
   - Verified that Checkout Store draft is created, tier is preselected, quote reflects R1,500.00 price, and Payment screen navigation completes without session errors.

2. **Repository-Derived Inbox Unread State & Query Invalidation**:
   - Added `social.conversationsRoot()` query key helper.
   - Derived `unreadInboxCount` dynamically in `feed.tsx` from `useConversationsQuery().data`.
   - Invalidated `conversationsRoot()` across message sending, reading, blocking, unblocking, and inquiry closing.
   - Added integration test verifying unread state clearing upon opening a thread.

3. **Repository Enforced Blocking & Inquiry Closing**:
   - `MockSocialRepository.sendMessage()` strictly validates conversation existence, target user blocking, and closed inquiry state.
   - Implemented `closeInquiry(conversationId: string)` in repository and exposed "Close Inquiry" action in `(modals)/conversation-actions.tsx`.
   - Updated `blockUser()` and `unblockUser()` to set `isBlocked` on all matching direct and inquiry conversations.
   - Added closed inquiry banner state ("This inquiry has been closed by the host.") replacing the message composer.

4. **Event Social Modules & Discussions**:
   - Created `app/(modals)/event-comments.tsx` modal sheet for event discussion comments.
   - Implemented `onMutate` optimistic pending comment state and `retryComment` mutation.
   - Added `<ReactionBar>` with like toggling and comments button directly into `app/(consumer)/events/[eventId].tsx`.

5. **Direct Thread Enhancements**:
   - Rendered distinct Voice Call (`phone`) and Video Call (`video`) icon buttons with separate accessibility labels.
   - Added repository operation `retryMessage(conversationId, messageId)` transitioning failed messages to `delivered`.
   - Connected `useSocialStore` for message drafts, setDraft, and clearDraft.
   - Added safe-area bottom inset padding around `MessageComposer` using `useSafeAreaInsets`.

6. **Error, Loading, and Invalid-ID Handling**:
   - Implemented explicit Loading, Query Error (with Retry), Empty State, and Invalid ID error branches across Inbox, Direct Thread, Inquiry Thread, and Report Content modals.

7. **New Message Modal & Target Validation**:
   - Updated `NewMessageModal` to read recipients from `mockSocialRepository.listMessageRecipients()`.
   - Strictly validated `ReportContentModal` target kinds (`"event" | "host" | "comment" | "message" | "user"`) and target IDs.

8. **Prototype Reset & Maestro**:
   - Connected `resetSocial()` and `mockSocialRepository.reset()` to `handleResetAll` in `prototype-controls.tsx`.
   - Created `.maestro/instruction-05-inbox-direct.yaml`, `.maestro/instruction-05-inquiry-booking.yaml`, `.maestro/instruction-05-social-states.yaml` (UNEXECUTED).

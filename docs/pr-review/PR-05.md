# PR-05 — Inbox, Direct Chat, Host Inquiries, and Social UI

## Objective

Rebuild the LIIT consumer messaging, host inquiries, and social coordination surfaces according to Instruction 5 product specifications and final review feedback.

Key implementations & corrections:
1. **CommentRow TypeScript Contract & Retry Control**:
   - Declared optional `onRetry?(): void` in `CommentRowProps` interface.
   - Rendered an accessible `Pressable` button when comment status is `"failed"` allowing users to retry posting failed comments with a stable `clientMutationId`.
   - Single cache row transitions `optimistic -> failed -> optimistic -> synced` without creating duplicate comments.

2. **Failed-Comment Lifecycle, Shared `submitComment`, & Controlled Draft Clearing**:
   - Refactored `handlePost` and `handleRetry` in `EventCommentsModal` to use a shared `submitComment` helper.
   - On mutation success, draft text in controlled composer is cleared conditionally (`setCommentText((current) => current === content ? "" : current)`), retaining the draft when initial post or retry fails, while preventing retry of an older failed comment from erasing a newer user draft.
   - Added `clientMutationId` to `PostCommentInput` and retained optimistic comments in cache on failure with `status: "failed"`.
   - Extended rendered comment retry test to assert:
     - draft retained in `composer-input` after initial failure (`value === "This comment will FAIL!"`);
     - draft cleared from `composer-input` after successful retry (`value === ""`);
     - single cache row;
     - single persisted comment record.

3. **MessageComposer Controlled Mode Draft Handling**:
   - Updated `MessageComposer` so controlled mode text (`value !== undefined`) is NOT cleared immediately on send; drafts are cleared only upon mutation success in parent components.

4. **Deterministic Alex Typing & Outgoing Message Statuses**:
   - Added deterministic typing timer effect in `DirectThreadScreen` for Alex Khumalo (`conv-direct-alex`), showing typing indicator at +1200ms and hiding at +4200ms with cleanup on unmount.
   - Added deterministic outgoing failed message fixture (`msg-alex-failed`).
   - Hardened `MockSocialRepository.retryMessage()` to enforce that only failed outgoing messages can be retried and transition them from `failed` -> `sent` -> `delivered`.
   - Used `useRetryMessageMutation()` in `InquiryThreadScreen` instead of duplicate message creation.
   - Added `dateHeader` ("Today") date separators in direct and inquiry thread message lists.

5. **Gated Booking Offers & Consumer Close Copy**:
   - Gated `BookingLinkCard` rendering in `InquiryThreadScreen` by `canUseBookingOffer = Boolean(bookingOffer) && !isClosed && !isBlocked`.
   - Updated consumer-closed inquiry banner text to `"You closed this inquiry."`.

6. **Mark-Read Effect Guarding & Repository Call Verification**:
   - Guarded `markReadMutation` calls in thread screens (`InquiryThreadScreen` and `DirectThreadScreen`) using extracted `unreadCount > 0` and stable function references to prevent infinite mutation triggers.
   - Updated `Instruction5InquiryThreadRendered.test.tsx` with `jest.spyOn(mockSocialRepository, "markConversationRead")` asserting that `markConversationRead` is called exactly once with `"conv-inquiry-club-vibez"`.

7. **Maestro Flow & Package Script Repairs**:
   - Fixed Maestro ticket tier selector in `.maestro/instruction-05-inquiry-booking.yaml` to `ticket-tier-tier-vip-tables`.
   - Updated `.maestro/instruction-05-inbox-direct.yaml`, `.maestro/instruction-05-inquiry-booking.yaml`, `.maestro/instruction-05-social-states.yaml` with `instruction-05` tags, app clear state, onboarding flow execution, and valid test IDs.
   - Added `test:e2e:instruction-05` package scripts to `package.json` and included `instruction-05` in `test:e2e`.

### 2.1 State architecture additions

| Module | Persisted key | Purpose |
|---|---|---|
| `useDemoClockStore` (new) | `liit-demo-clock-v1` | Fixed base `DEMO_NOW_ISO` + advance offset; `useDemoNowIso()` hook replaces raw `DEMO_NOW_ISO` at consumer screens so wallet/ticket/status classification follows the demo clock. |
| `usePrototypeControlsStore` (new) | `liit-prototype-controls-v1` | Development-only failure toggles: `saveFollowFailure`, `commentFailure`. |
| `usePrototypeOverridesStore` (new) | `liit-prototype-overrides-v1` | Per-event status overrides (`live | sold_out | completed | cancelled`) applied in mock discovery/event/map repositories (override wins over scenario transforms). |
| `useDiscoveryStore` (existing) | `liit-discovery-state-v1` | Optimistic save/follow lives in a new `useSaveFollowActions` hook (flip → 400ms latency → revert + toast on simulated failure/offline). |
| `MockNotificationRepository` | `liit-notifications-v1` (new) | Notifications become persistent (read state survives restart); adds `recordTicketConfirmed` / `recordRegistrationConfirmed` with monotonic `notif-{n}` ids. |
| `MockTicketingRepository` | `liit-ticketing-repository-v1` | Adds `setTicketStatus(ticketId, status)` (persisted, monotonic sequence unchanged); auto-publishes ticket/booking notifications via injected `NotificationRepository`. |

### 2.2 Journeys mapping

- **J1** (first launch → discovery): already implemented in PR-01/02 (welcome → location choice with denied → manual Johannesburg → interests → guest/sign-in → Feed; resume without replay; reset via controls). Verify + test coverage; no rework expected.
- **J2** (discover/save/follow): filters already stateful and shared across Feed/Explore/Search/Map. NEW: store-driven `isSaved` + save button on Feed/Explore/Search cards; optimistic save/follow with visible revert (failure toggle + offline); Profile stats/tabs driven by `savedEventIds`/`followedHostIds`; new Following tab + `profile/following.tsx`.
- **J3** (paid booking): checkout/quote/fees/attempt atomicity exist. NEW: paid success auto-creates `ticket_confirmed` notification; offline scenario resolves payment as network error; retry retains cart (exists).
- **J4** (free registration): idempotent registration exists. NEW: `booking_confirmed` notification on registration; Event Detail shows "Registered — view pass" (and "You have tickets — view ticket" for paid) using wallet state, so repeated registration is visibly prevented.
- **J5** (social): NEW: inquiry entry from Event Detail ("Ask about this event") and Host Profile (Message) that resolves to the matching inquiry conversation or the new-message modal; deterministic simulated host reply + typing for `conv-inquiry-club-vibez` (once per reset, persisted flag); comment failure toggle in Prototype Controls (recoverable by retry).
- **J6** (tickets): statuses exist. NEW: Prototype Controls "set ticket status" (pending/valid/used/cancelled) via `setTicketStatus`; demo clock drives wallet upcoming/past and ticket validity presentation.
- **Notifications**: rows navigate to event / host / message / tickets contexts (message target + `social_message` fixture added); read state persists; mark-all-read persists.

## 2. Objective & Completed Scope

Turn the consumer surfaces from PRs 1–5 into a connected, locally stateful product: production-shaped repository boundaries, deterministic prototype simulations, and development-only scenario controls — no backend, no network required.

- **J1 — First launch**: welcome → location choice (denied continues with manual Johannesburg) → interests → guest/simulated sign-in → Feed; returning sessions resume without replay; reset via Prototype Controls (pre-existing, verified + covered).
- **J2 — Discover/save/follow**: Feed/Explore/Search/Map share the same event entities and filters; save/follow are optimistic with a simulated failure toggle that visibly reverts (400ms); offline scenario also reverts; Profile Saved/Following counts and content are store-driven; new Following tab + `profile/following`.
- **J3 — Paid booking**: quantity limits, 5% fee quote, atomic attempt guard (no double submission), Processing passes through visibly, paid success creates order + wallet ticket + `ticket_confirmed` notification; decline/network-error create nothing; offline resolves as network error; retry retains the cart.
- **J4 — Free registration**: idempotent registration creates order + pass + `booking_confirmed` notification; Event Detail converts to "View your pass" after registering (repeated registration visibly prevented); paid events show "View your ticket".
- **J5 — Social coordination**: "Ask about this event" (Event Detail) and Message (Host Profile) resolve to the matching inquiry conversation or the new-message modal; inquiry threads simulate host typing + a deterministic once-per-reset host reply; direct-thread send flow unchanged; comment failure toggle (recoverable via retry); report/block unchanged.
- **J6 — Ticket use**: Prototype Controls can set any wallet ticket to pending/valid/used/cancelled (persisted); demo clock drives wallet upcoming/past and validity classification; Full Ticket presentation follows status (QR only when valid, non-scannable placeholder).
- **Notifications & deep links**: rows navigate to event / host / message / tickets / search / profile contexts; read state and mark-all-read persist across restarts; booking actions create notifications automatically; new `social_message` fixture with message target.
- **Hidden Prototype Controls**: failure toggles (save/follow, comment), per-event status override (live/sold_out/completed/cancelled, override wins over scenarios), ticket status override, demo clock (+1h/+6h/+24h/reset), existing Reset All extended to the new stores.

## 4. Assumptions & Deliberate Deviations

1. **Seeded wallet tickets are demo history** — Event Detail shows "View your pass / View your ticket" only for session-created bookings (non-`ticket-liit-seed-*`), preserving the accepted "Choose tickets"/"Register free" checkout entry flows.
2. **Inquiry entry for fixture hosts** — no discovery host has an inquiry conversation, so Event Detail "Ask about this event" and Host Profile Message deterministically open the new-message modal, which routes inquiry-kind recipients into the inquiry thread (journey fully demonstrable).
3. **Simulated host reply scope** — canned replies exist for `conv-inquiry-club-vibez` and `conv-inquiry-soweto-market`, once per reset.
4. **Comment failure toggle** — fails the first post per `clientMutationId`; retry after toggling off succeeds.
5. **Web static export** — pre-existing Node-SSR limitation (AsyncStorage in the static renderer); Android Hermes bundle export succeeds (verified).
6. **Lint** — 20 warnings (15 pre-existing + 5 `no-require-imports` in new test mock factories, matching the accepted Instruction 5 test pattern); 0 errors.
7. **Format** — `prettier --check` on all files changed in this PR passes; the repo-wide check fails on 60+ pre-existing files untouched by this PR (drift present on `main`).

1. **First launch (J1)**: fresh install → onboarding carousel → "Simulate Denied Permission" → tap **Johannesburg** → Continue → interests → "Simulate Sign In" → Feed. Relaunch the app → Feed directly (no onboarding replay). Prototype Controls → Reset Onboarding → relaunch → welcome replays.

3. **Filters shared (J2)**: Search → Filters → set category/price/availability → results change; Map → filters → switch Map/List → same filtered set.
4. **Paid booking (J3)**: Event Detail (Midnight Kinetic Grooves) → Choose tickets → qty 2 → order summary recalculates (5% fee) → Payment → Pay (duplicate taps blocked) → Processing → "Tickets confirmed!" → wallet shows the new ticket; Notifications list contains "Tickets confirmed". Prototype Controls → **Payment Decline** → retry the same cart from the result screen; **Payment Network Error** → same; **Offline State** → Pay resolves to network error.
5. **Free registration (J4)**: Soweto Street Food & Craft Market → Register free → confirmation → wallet pass; return to Event Detail → "View your pass" (registration visibly already recorded). Notifications contains "Registration confirmed".
6. **Social (J5)**: Event Detail → **Ask about this event** → new-message modal → pick a host recipient → thread; send a message → delivered state; open the Club Vibez inquiry from the Inbox → typing indicator then the host's canned reply appears (once per reset). Prototype Controls → **Simulate Comment Failure** → post a comment on an event → fails once → toggle off → retry succeeds.
7. **Tickets (J6)**: Tickets tab → Full Ticket (valid → QR placeholder) → Prototype Controls → Ticket Status Override → set to Used/Cancelled → ticket moves to Past; +24h demo clock → event-ended tickets classify as Past.
8. **Notifications (J1–J6 links)**: tap each notification row → Event Detail / Host Profile / Inquiry Thread / Wallet / Search / Profile; mark-all-read persists after relaunch.
